# NextGen ERP Desktop — Test Report

**Build:** v7 development milestone 15 (schema version 9; role and theme preferences use additive settings metadata)  
**Date:** 2026-10-24  
**Environment:** Windows, Python 3.10.9, PySide6 6.12.0, Qt offscreen platform

## Checks run

- `python -m unittest discover -s tests -v` — **60 tests passed**.
- Python bytecode compilation and AST parsing for all project Python files — passed.
- Authentication lifecycle tests use isolated temporary SQLite databases and the actual setup/login dialog methods. They cover first-run validation, persistence of business name/profile/currency/theme and starter modules, administrator creation, rejection of a bad password, acceptance of valid credentials, rejection of an inactive account, and sign-out followed by successful sign-in on the existing window with its timer stopped. Import and offscreen Qt page construction are exercised by the UI smoke tests. An isolated Windows profile was launched directly into the ERP shell and visually inspected in light and dark mode at 1274×720; it did not use a real business database.

The suite covers first-run administrator creation, public-default credential rotation, role action grants and module visibility persistence/enforcement in the Store and core operations service, custom role creation from least-privilege templates, custom role grants and module enforcement, protected-grant rejection, account role assignment and safe deletion checks, light-theme first-run default, theme switching with active and cached form state preserved, palette contrast across brand accents, profile changes preserving user data, retaining access to data-bearing modules and their dependencies, blocking manual disable of modules with saved records, module dependency enforcement, profile dependency validation, module grant access and persistence, role-specific dashboard widget persistence/rendering, ledger-backed low-stock counts and actionable dashboard list with Inventory permission filtering, configured sales tax settings, calculation, quote/return snapshots and document rendering, Settings UI persistence, legacy v2/v6 migrations and v8-to-v9 product catalog migration (category and barcode columns), module enable/disable, inventory-backed sales, quote acceptance/conversion, purchase orders, partial receipts, linked receipt cancellation and weighted-cost restoration, escaped printable invoice/quote/order/receipt HTML, oversell rejection, item-level returns with paid-amount limits and restock choices, cancellation after partial returns, repair intake through approval, parts, tax, payments and collection, repair module permission enforcement, cash totals, database restore migration, safety backup preservation, invalid-backup rejection, account reset/disable behavior, role-specific navigation, module and dashboard-widget controls in the administration UI, safe custom field metadata validation and Store-level required/type/choice/date validation, and construction of the operational UI pages, including the dedicated Repair Tickets workflow.

## Limits of these results

- First-run configuration and authentication behaviors were exercised through the dialog methods with isolated test data, not by visually typing into the login/setup dialogs. Startup setup now captures the business name, starter profile, currency and theme, and applies the profile module layout. The Store enforces configured required, text, number, date, and choice rules for custom records and rejects invalid field metadata at creation. Full process restart and startup cancellation were not exercised end to end. Initial setup does not yet capture the full business identity, logo, locale/time zone, receipt numbering, or detailed workflow configuration called for in the handover.
- The live Windows preview covered only the dashboard shell at 1274×720. Other modules, settings forms, login/setup dialogs, smaller laptop viewports, and clipping have not been visually verified.
- Physical printer behavior and rendered print previews were not tested. The build includes branded HTML templates for invoices/receipts, quotations, purchase orders, goods-received notes, and repair job sheets, and offers 58/80 mm, A6, A5, A4, A3, Letter, and Legal sizes. No printer was available to verify scaling, pagination, or output quality.
- Cloud sync was not tested against a compatible server.
- Restore and migration tests used synthetic databases. Back up a real business database before upgrading or restoring it.
- Profile-specific automatic dashboard presets, tax-inclusive pricing, purchase/input tax, per-product tax categories, double-entry accounting, customer credit and balances, advanced quote revision/terms workflows, supplier delivery notes, logo management, and complete industry-specific workflows are not implemented in this milestone. Repair Tickets covers a focused device service workflow; other industry workspaces remain configurable records.

This report describes checks actually performed; passing tests do not establish production readiness or replace a customer-data migration rehearsal.
